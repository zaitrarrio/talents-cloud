GATE — description-extraction fix (2026-11-11)
=============================================

ROOT CAUSE
----------
File: src/validate.ts — parseSkillFrontmatter, the hand-rolled
line-based SKILL.md frontmatter parser shared by every ingest path
("flat scalar keys only"). Two defects:

1. NO YAML BLOCK-SCALAR SUPPORT. For `description: |` (literal) or
   `description: >` (folded), the parser stored the indicator character
   as the value and then appended each indented content line through
   its plain-scalar continuation rule, space-joined. Stored result:
   "| Preregister a paid eval …" / "> Routes any game-development
   request …". Block scalars are the most common way published
   SKILL.md files write long descriptions, so this was catalog-scale.

2. NO SANITY GUARD ON THE VALUE. A frontmatter description that is
   literally debris IN THE SOURCE passed the non-empty check and was
   stored verbatim:
   - dnyoussef/context-cascade writes `description: ---` in its
     SKILL.md frontmatter (verified at the pinned ref: the file itself
     says `description: ---`). The parser read it faithfully; nothing
     rejected a delimiter as a description.
   - shivamchopra7/claude-skill-directory's agent-creation SKILL.md
     carries a banner rule as its first frontmatter description:
     `description: /====…====/`.

FIX (code)
----------
- src/validate.ts: parseSkillFrontmatter now parses block scalars
  properly (literal keeps line breaks, folded folds them; chomping
  +/- and indent indicators handled; following keys not swallowed).
  New shared helpers: isUsableDescription (usable = contains at least
  one letter or digit, Unicode-aware), usableDescription (first
  usable candidate, else ""), bodyDescription (first ATX heading or
  first usable paragraph of the SKILL.md body; thematic breaks, HTML
  comments and banner debris skipped).
- Description picks now go through the guard on every ingest path:
  src/repo-scan.ts (frontmatter → body heading/paragraph → none),
  src/ingest.ts (marketplace entry → plugin.json), src/declaration.ts
  (debris descriptions no longer quoted into declaration lines),
  src/discovery/scouts/mcp-record.ts and npm-record.ts.
- src/discovery/pipeline.ts: ingestSource now REFRESHES an
  already-listed record when the rebuilt record's attestation content
  hash or description differs (fresh attestation from the builder +
  the store's existing upsertRecord write — the pipeline's own
  semantics, no fork); identical rebuilds are still skipped, so sweep
  re-ingests stay cheap. Return/CycleStats/CLI gained existingUpdated.
