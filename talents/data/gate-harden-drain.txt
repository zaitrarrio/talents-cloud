   max 100): reports dlqDepth + every entry's failure class, re-enqueues
   recoverable ones (source still candidate + class rate-limit/network/
   server/unknown) up to the cap, leaves the rest for operator review.
   Nothing auto-deletes from the DLQ. GET /admin/drain-health serves the
   stall snapshot. The daily cron logs DLQ depth + candidate count.
   The queue handler writes the DLQ manifest (dlq_entries) on the FINAL
   attempt (attempts >= 4 = 1 + max_retries 3) with the failure class.
3. RATE-LIMIT BACKPRESSURE — githubAuthedFetch records GitHub's rate-limit
   headers (FetchFn now carries optional headers; defaultFetch passes the
   real Response headers through): 403/429 sets github_rate_exhausted_until
   (Retry-After wins, else x-ratelimit-reset, else a 60s hold); remaining
   < 1000 snapshots github_rate. The producer halts while exhausted; the
   consumer checks the flag before ANY GitHub call and throws
   RateBudgetExhaustedError → Queues retries later.
4. IDEMPOTENCY / LEASE — consumer claims a 30-min lease (claimed_at /
   claimed_by, migration 0007) after locator collapse and before the first
   GitHub call; a lost claim throws LeaseConflictError → retry. Terminal
   outcomes clear the lease + record drain:terminal / drain:last_terminal_at.
   Leases are advisory (idempotent ingest is the real safety net) and
   deliberately NOT part of SourceRow/upsertSource, so status upserts
   never clobber them. Stale leases (>30 min) are reclaimable.
5. SANDBOX-DRAIN DECONFLICTION — backfill-drain.mjs skips locators with an
   active queue lease, claims the same lease per batch (dropping rows that
   lose the race), clears batch leases at batch end, and waits 60s instead
   of hot-spinning when everything left is leased. Defensive typeof guards
   so the script degrades to unleased behavior against an old dist snapshot.
   The dist snapshot was rebuilt (npm run build && cp -r dist .dist-snapshot;
   LEASE_TTL_MINUTES=30 verified present) so the watchdog's next relaunch
   picks the lease-aware script up. The running drain keeps its old code
   until it dies/restarts (harmless: ingest is idempotent).
6. STALL DETECTION — drainHealth(): stalled when DLQ non-empty, or no
   terminal completion in 3h while candidates remain and messages are
   inflight, or the producer is enabled but starving the queue (no
   inflight, no recent terminal, candidates waiting). Served by
   GET /admin/drain-health; the producer tick logs STALL lines. The
   existing watchdog cron was NOT touched.
