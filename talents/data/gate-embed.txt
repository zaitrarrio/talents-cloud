PROBLEM (from data/gate-backfill.txt)
  The old POST /admin/embed loaded EVERY listed record into one
  Worker invocation before embedding any of them. Past a few
  thousand records it hung and returned 500 D1_ERROR under the
  drain's import contention, so Vectorize covered only a minority
  of the catalog while FTS carried search alone.

THE CHANGE
  POST /admin/embed now accepts { limit, cursor } and processes ONE
  bounded page per call (default 100, max 500), ordered by record
  id, returning { considered, embedded, skippedFresh, nextCursor,
  done }. A no-body call processes just the first page — the
  all-records scan is gone. Implementation reuses the existing
  indexer (same text-hash + model staleness rule, same keying:
  vector id = sha256(record id) in embedding_meta.vector_id,
  Workers AI @cf/baai/bge-base-en-v1.5 into talents-skills):
    src/discovery/embeddings.ts  indexStaleRecordsPage (+fetcher)
    cf/src/db.ts                 recordsPage (id > cursor, SQL)
    cf/src/discovery.ts          handleAdminEmbed wired paged
    scripts/backfill-embed.mjs   cursor-threading driver (backoff,
                                 page-halving, straggler sweeps)
