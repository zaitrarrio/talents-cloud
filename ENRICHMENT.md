Scope: every listed record (skills, plugins, MCP servers/connectors) discovered by any
channel. Enrichment is a pipeline stage of its own — not part of verification (which
decides listing) and not part of ranking (which consumes enrichment as input).

## Principle: three kinds of enrichment, always labelled

Every enriched field carries a provenance class, and the classes are never blended
in storage or display:

- **source** — fetched facts from the origin (GitHub/npm/registry). Shown plainly.
- **derived** — deterministic extraction from source artefacts (parsing, counting,
  protocol introspection). Shown plainly; method is mechanical, not editorial.
- **generated** — LLM-produced editorial content (Anthropic; provider decided
  2026-11-10). Always labelled "Generated" in UI and API; never overwrites a
  source field; search-indexed at lower weight than source text.

## A. Source facts (class: source)

Per record, refreshed on the freshness cadence:
- GitHub repo: stars, forks, watchers, open issues, license (SPDX), topics,
  primary language + language mix, created/pushed dates, archived flag,
  default branch, contributor count (bounded), release cadence (latest tag/date).
- npm package (when applicable): weekly/monthly downloads, latest version +
  publish date, version count, maintainers count, deprecated flag.
- MCP registry (when applicable): registry version history, namespace verification
  status where the registry asserts it.
- README: fetched and stored (R2 — display assets only, per architecture);
  rendered excerpt on the skill page; first suitable image / repo social preview
  as the record's icon, stored in R2 with its source URL recorded.

## B. Structural deepening (class: derived)

Beyond today's component counts:
- Collections expanded: every contained skill/agent/command inside a plugin or
  collection repo gets its own name + description entry (sub-inventory), so a
  40-skill collection is searchable per-skill, not just as a blob.
- SKILL.md full parse: frontmatter fields (allowed-tools, model, license),
  instruction size (lines/tokens), referenced files/scripts inventory,
  external URLs referenced in instructions.
- plugin.json / marketplace fields: author, homepage, repository, keywords.
- MCP package records: package name/version/registry, transport (stdio/http),
  environment variables the server requires (names only, never values),
  from server.json / package metadata.

## C. Live MCP introspection (class: derived)

For remote MCP servers (http transport with a public endpoint):
- Connect read-only: `initialize` + `tools/list` (+ `resources/list`,
  `prompts/list` where offered). NEVER invoke a tool.
- Store the real tool inventory (names + one-line descriptions) — this upgrades
  the declaration from "tools unknown" to a concrete inventory.
- Timeouts + size caps; failures recorded as introspection status, not errors
  against the record. Refresh on a slow cadence (weekly) and on registry update.
- Local (stdio/package) servers: introspection v1 is static only (section B);
  sandboxed execution is out of scope for this tranche.

## D. Generated editorial (class: generated, Anthropic)

Produced once per source-hash; regenerated only when the source hash changes:
- Summary: one-line + short paragraph, grounded ONLY in source artefacts
  (README, SKILL.md, descriptions) supplied as context; no outside knowledge.
- Tags + categories: assigned from a fixed Talents taxonomy (maintained list);
  list-repo section headings and marketplace categories are inputs, not output.
- Use cases: 2–4 concrete "jobs" phrased as user goals (feeds the advisor and
  goal search); audience hint (developer / ops / data / creative / general).
- Quality gates: summary must not contradict source description (cheap
  entailment spot-check on samples); empty/thin sources get NO generated layer
  rather than a padded one ("insufficient source material" is a valid state).

## E. Trust signals (class: derived)

- Risky-pattern static scan v1 over SKILL.md + bundled scripts: remote code
  execution patterns (curl|bash, eval of remote content), credential-file
  access, persistence mechanisms, obfuscation markers. Findings are factual
  flags ("references ~/.ssh", "downloads and executes a remote script"),
  displayed as neutral facts, feeding P3 — not verdicts.
- Freshness: last-verified timestamp, source-drift status (hash changed since
  attestation → re-verify queue), enrichment staleness per layer.

## F. Completeness + provenance

- Per-record enrichment state: per layer (A–E) one of done / partial / none /
  stale, with timestamps and (for D) model + source-hash.
- A completeness score (internal + creator dashboard) — publishers see exactly
  which enrichment their listing lacks, which is the lever that gets READMEs
  and descriptions improved at the source.

## Pipeline mechanics

- Stage order: discover → verify → ingest → attest → **enrich** → embed → rank.
  Enrichment failures never unlist a record; they degrade its completeness.
- Idempotent, keyed by (record id, source hash): unchanged source = no rework,
  except A-layer repo stats and C-layer introspection, which refresh on cadence.
- LLM cost discipline: D-layer only for listed records with sufficient source
  material; batched; cached by source hash. Report cost per 1k records in the
  gate, with the actual figure.
- Storage: `enrichment` table (next migration number after the creator build's),
  keyed by skill_id, JSON per layer + state columns; images in R2 with source
  URLs recorded (never hot-linked, never the only copy of a source URL).

## Sequencing (as of 2026-11-10)

- The creator-experience build owns render.ts and the current migration slot;
  enrichment display integration starts when its gate lands.
- The backfill (running) grows the catalog first; enrichment then processes the
  enlarged catalog in completeness order (most-trafficked records first, using
  record_stats), not discovery order.
- Gate: per-layer coverage % over the listed catalog, 10 sampled records
  inspected by hand against their sources, D-layer label present everywhere
  generated text appears, C-layer tool inventories sampled against a manual
  MCP client session, cost report for the D layer.
